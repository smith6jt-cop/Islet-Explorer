# Browser source security scan

Run from the checkout with R/jsonlite, Node, Python 3, curl and Semgrep **1.176.1** installed:

```sh
bash deploy/scan-browser-code.sh --output /tmp/islet-browser-sast
# Replay the exact reviewed rules, without fetching an updated registry snapshot:
bash deploy/scan-browser-code.sh --output /tmp/islet-browser-sast-replay \
  --rules /tmp/islet-browser-sast/javascript-rules.yml
```

`SEMGREP_BIN` can select an isolated Semgrep installation. Output directories must
be new. CI installs the same pinned version and retains run evidence for 90 days;
download the successful final-commit artifacts into the durable review packet.

The only network request is downloading the official `p/javascript` rules from
`https://semgrep.dev/c/p/javascript`. Scanning uses that saved local snapshot,
the OSS engine, disabled metrics/version checks/tracing/remote validation, and
no authenticated platform connection. Source files are not uploaded. The rule
snapshot SHA-256 identifies the rules precisely; registry contents may change
between runs. Evidence includes the exact rules, tool version, Git identity,
source hashes, extracted source origins, syntax checks and complete scan JSON.

The deployed authored `.js`/`.mjs` files and inline HTML script bodies are copied
into an isolated scan tree. `scripts/extract_browser_scripts.R` parses application
R syntax and recursively collects literal strings with JavaScript
function/document/window/Shiny syntax. It never sources or evaluates R code.
Anonymous function literals receive expression wrappers and `sprintf` arguments
receive synthetic values; every transformation and source line is recorded.
R parse failures and Node syntax failures stop the scan. Semgrep findings,
engine/rule/parse errors, or a mismatch between expected and scanned target
counts also fail. Findings cannot be hidden with `nosemgrep` comments.

This is scoped static analysis. It does not establish cross-language taint flow,
validate values substituted by R at runtime, discover every dynamically
assembled script fragment, or cover scripts generated by installed R packages.
Developer browser/test tools are outside the deployed-source target set. The
checked-in Avivator `assets/` bundles are excluded from this authored-source
scan and are assessed separately through vendor hashes, provenance, dependency
inventory and Retire evidence. These limits remain part of the review record;
a passing scan is not a general security certification.
