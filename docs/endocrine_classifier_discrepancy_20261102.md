# Endocrine classifier / typing discrepancy — 2026-11-02

The classifier and the later cell-typing step use different spatial units, preprocessing and thresholds. **The data do not show that the classifier detected 7,800 objects without endocrine signal.** They show 7,800 unresolved **cells** whose corrected whole-cell measurements fail the later positivity rules. Original classifier signal is still present in most of those cells. Some final cell-based objects also extend away from the original detected signal.

The owner's direction is: “The classifier is trained with INS, GCG, SST, and CHGA so it cannot be possible for the endocrine objects to be negative. Resolve this discrepancy.” This supersedes the earlier question about sending these cells to general typing or excluding them. Neither disposition follows from a negative corrected mean.

**Status:** the causal discrepancy is traced to actual source code and images; checks are corrected. Existing v20 measurements and identities remain unchanged and are not accepted for production. The audit does not establish replacement identities or justify forcing hormone names.

## Where the two definitions diverge

1. **Original detection:** `islet_classifier_fit.py` fits per-image thresholds on the original INS/GCG/SST/CHGA image planes. Hormone pixels seed the mask; CHGA widens it near hormone signal. The classifier uses a Gaussian blur (sigma 1 µm), a 0.7548 µm pixel grid, closing/opening and a margin. QuPath then refines vector annotations and fills holes. Detection of a positive region does not require every pixel inside its final outline to be positive. T1D_6563's fitted INS threshold is null, so that particular classifier uses the other three channels.
2. **Whole-cell outlines:** `qupath/1b_islet_outlines_to_cells.groovy` first selects cells with at least 50% of their area covered by an original object. When none qualifies, it chooses the available cell with the largest positive overlap, **with no minimum overlap**. A single-cell object then becomes that cell's entire outline. This can transfer an object's designation onto a cell next to its signal.
3. **Later positivity:** `typing/levels.py` uses independently selected thresholds on **REDSEA-corrected whole-cell means**, after native-resolution 3×3 median filtering. The endocrine cutoff is the 99.9th percentile in its distant tissue reference. `identity.py` compares these log1p values and levels. Its `no_endocrine_marker_above_level` reason means failure of this later comparison; it is not a measurement of absent classifier signal.
4. **The missing check:** the level-selection code reports endocrine-object sensitivity but its existing endocrine acceptance criterion checks false positives in the distant vascular reference. It did not require the four markers together to recover each final endocrine object. The identity code could then retain an object name, and assembly could count unnamed cluster/single cells as endocrine while the UI counted only named endocrine types.

The thresholds cannot be exchanged numerically: pixel intensities and corrected whole-cell means are different quantities. Current INS and SST thresholds are numerically lower than the original classifier thresholds on every image where both exist; a blanket claim that the new cutoffs are simply higher is false.

## Corrections implemented

* **Joint object-positivity gate (`9127f52`):** `typing/endocrine_object_audit.py` reads selected levels, REDSEA measurements, context and final geometries directly, before identity typing. It verifies the exact cell join and matching eligibility, requires at least one eligible INS/GCG/SST/CHGA-positive member per object, and checks single-object membership. It writes object-level failures and source hashes to a fresh report. `levels.py` invokes it using the levels it just wrote, including `--report` trials, and fails the run when the check fails. It does not require all islet cells to be positive. HPG job **49072173** returned the expected exit code **4**, rejecting all 948 fully negative objects and three membership anomalies. Every common field for all 10,080 objects matches the independent identity-based audit. All four returned reports match HPG hashes. This tested the standalone gate against actual data; the full level-selection workflow was not rerun against the immutable historical root.
* **QuPath diagnostic parity (`5629465`):** the Python `script1_objects()` approximation omitted QuPath's final all-hole fill. The installed QuPath 0.7.0 APIs were inspected: initial pixel-object creation and final `RefineAnnotationsPlugin` give `-1` different meanings. The approximation now fills holes per retained object after fragment removal. All 20 real archived masks pass the comparison; 719,212 pixels are added, 99.35% inside actual QuPath outlines, and foreground IoU improves from 0.93777 to 0.97271. Existing labels remain intact. This affects diagnostic `.objects.npy`/reports only: the function runs after threshold fitting and mask creation. It did not cause v20's cell calls and does not alter its fitted classifiers.
* **Release protection:** the earlier `6cee485` change rejects unnamed endocrine identities and inconsistent assembly/UI endocrine membership. The immune-gradient correction remains part of the required future release.

The classifier, original object geometry, protected REDSEA implementation, positivity levels and existing cell identities have not been replaced. The hole-fill fix retains a known approximation: a single label raster cannot represent overlapping nested QuPath annotations; it preserves the nested label and the foreground union.

Syntax/CLI checks and independent code review pass. No synthetic cases were added. The object gate intentionally does not resolve unnamed members inside otherwise positive objects; the separate release identity check remains necessary. Standalone default image discovery reads available final geometry filenames; `levels.py` supplies the complete selected cohort explicitly, so it also detects missing selected-image inputs.
