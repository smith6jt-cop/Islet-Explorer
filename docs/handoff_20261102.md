## Procedures and lessons

- **Release sequence**, using the untracked helpers in `tmp/ufrc-release-20261022/`:
  1. Move the clean release worktree: `git -C /data/panc_CODEX/Islet-Explorer-release-20261022 checkout --detach <commit>`.
  2. `RELEASE_NAME=<name> ./build-image.sh`
  3. `SOURCE_ROOT=<root> ./build-data.sh`
  4. `SOURCE_ROOT=<root> ./verify-data.sh`
  5. `RELEASE_NAME=<name> ./bind-release.sh`
  6. `RELEASE_NAME=<name> INSTANCE=islet-explorer-dev PORT=3839 MEMORY=6g PUBLISH_ADDRESS=10.13.41.21 ./deploy-vm.sh`

  Tool versions: Syft and Grype are in `~/.local/bin`, rootless Podman on the workstation. See `deploy/README.md`
  §§ 1–4.
- **Parity requires matching commits.** The parity check refuses a bundle whose commit differs from the checkout it
  runs in, so a fix to the builder or the parity script means rebuilding the image and the bundle. Shake out
  builder and parity failures on a cheap trial bundle first (`build_release_data.R --materialize hardlink`).
- **Smoke the release locally before the VM.** Run the release image on the bundle with `deploy/run.sh`'s flags
  (127.0.0.1:3843). Read its log for `trajectory_warm_ok`, then run `check-app.mjs --expanded true`. The warm-up runs
  only with `ISLET_RUNTIME_MODE=production`, so the dev app never shows it.
- **Gate failures.** The Grype database refreshes daily, so a rebuild days later can fail on new advisories. Pin the
  fixed versions as in `deploy/BASE_HARDENING.md` (2026-10-22, 10-25, 11-01).
- **Acceptance through the proxy**, from the workstation:
  - `python3 deploy/verify-reviewer-access.py --url https://devislet-explorer.rc.ufl.edu/islet-explorer/ --image-path local_images/ND_0112.ome.tiff --image-prefix-sha256 e4dad33db3d9256a61624cfb20a2eeb8a925d20c33d7826290dcafd846d6cc24 --sidecar-path local_images/ND_0112.ome.xml --sidecar-path local_images/ND_0112.offsets.json --auth-file ~/restricted/dev-auth.json --output <json>`
  - `node deploy/browser/check-app.mjs --url <same> --auth-file ~/restricted/dev-auth.json --expanded true --output <json>`
- **HiPerGator.** Commands, the rules (never run a whole-tree rsync or git checkout into the sealed tree; only HPG
  writes data) and resealing are in `docs/hpg_processing_20261031.md`. `ssh hpg` is the owner's ControlMaster; when
